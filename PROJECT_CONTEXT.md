## Architecture
```
Assets/_Game/
  Scripts/Runtime/            asmdef Gamebreak.MiniGolf (no world-specific code in Core/Player)
    Core/      GolfBall, Putter, Cup, HoleController, CourseController, GolfTuning, GolfMaterials, OutOfBoundsZone
    Course/    CourseGeometry (green mesh with real cup hole + rails), HoleDefinition, HoleFactory, TropicalCourse
    Player/    VRRig (tracking, teleport, snap turn, grab-move, putter adjust, handedness), HandInput
    UI/        WristDisplay, ScorecardPanel, WorldText, DebugOverlay (monitor-only)
    Debug/     SmokeTest (-smoketest built-player test), SessionLog (per-session play log)
    Feedback/  GolfFeedback (synthesised SFX + haptics)
    Worlds/    WorldTheme (per-world materials and lighting)
  Scripts/XR/                 SteamFrameControllerProfile (native Frame input)
  Scripts/Editor/             ProjectSetup, SceneBuilder, Automation (batch entry points, screenshots, scene stats)
    Art/       Palette, TextureGen, MeshBuilder, KitMeshes, TropicalKit, IslandGen, Dresser, TropicalWorld
  Art/Shaders/                StylizedLit, StylizedWater, GradientSky (URP, SPI-safe)
  Tests/PlayMode/             physics and putter tests
  Worlds/Tropical/            scene, theme; Kit/ = generated meshes + materials (regenerated by the scene build)
  Resources/GolfTuning.asset  every feel number in one place
Tools/WalkaboutProbe/         measurement-only MelonLoader mod + analysis script
```

Key design decisions:
- **Putter** follows the controller exactly and never collides with the course. Strikes come from a swept box-vs-ball test each frame using smoothed head velocity: speed = normal speed x `energyTransfer`, direction = blend of face normal and swing path (`faceAngleWeight`). No PhysX putter-ball contact, so no tunnelling at fast swings and no jitter.
- **Ball** owns its velocity integration: 5/7 g on slopes (rolling sphere), rolling resistance `a0 + k*v`, static hold on gentle slopes, wall rebounds from pre-contact velocity (restitution + rail friction), capped lip hops. PhysX only resolves contacts (all friction and bounce = 0). 120 Hz physics, continuous collision.
- **Greens** are one generated mesh per hole: grid surface from a height function, a real cup hole and cup, and rail mesh around the outline. Holes are layout data in code (`TropicalCourse`).
- **Worlds** are data: `WorldTheme` + hole definitions + set dressing. Golf code never references a world.
- Scenes are generated by `SceneBuilder` (`Gamebreak/Build Tropical Scene`) so they are reproducible from code.

## Batch commands
```
Unity.exe -batchmode -quit -projectPath <repo> -executeMethod Gamebreak.MiniGolf.Editor.Automation.Setup             # configure + rebuild scene
Unity.exe -batchmode -quit -projectPath <repo> -executeMethod Gamebreak.MiniGolf.Editor.Automation.SetupAndBuildAll   # + PCVR and desktop players
Unity.exe -batchmode -quit -projectPath <repo> -executeMethod Gamebreak.MiniGolf.Editor.Automation.CaptureScreenshots # Screenshots/ per hole
powershell -File Tools\run-tests.ps1      # PlayMode suite with a one-line-per-test summary
%LOCALAPPDATA%\Unity\bin\unity.exe test . --mode PlayMode --output Logs/cli-results.xml --non-interactive   # same suite via the Unity CLI
powershell -File Tools\smoke-test.ps1     # built desktop exe: scripted putt, progression, screenshots
```
Do not pass `-nographics` for builds or screenshots. Builds take about 4 minutes (clean cache each time).

| Output | Path |
|---|---|
| PCVR player | `Builds/Windows/WorldsOfMiniGolf.exe` |
| Desktop debug player (no XR) | `Builds/Desktop/WorldsOfMiniGolf_Desktop.exe` |
| Smoke test report/screenshots | `Builds/<build>/SmokeTest/` |
| Player log | `%USERPROFILE%\AppData\LocalLow\Gamebreak Labs\Worlds of Mini Golf\Player.log` |
| Session logs (strikes, holes, frame times) | same folder, `Sessions\` |

Unity gotcha: every MonoBehaviour/ScriptableObject must be in a file with the same name. The build is blocked automatically if one isn't.

## Art pipeline (World Forge, current form)
Art is generated in code so it is original, versioned and easy to vary:
1. **Kit** (`TropicalKit`): palette texture + shared materials + named meshes from `KitMeshes` generators (seeded).
2. **Island** (`IslandGen`): analytic height function; hole sites become flatten zones automatically; paths between holes; ocean with baked shore distance.
3. **Dressing** (`TropicalWorld` + `Dresser`): per-hole `DressHoleN` methods in hole-local coordinates, plus seeded island scatter that keeps clear of greens and paths.
4. **Safety**: obstruction scan removes scenery on greens; test `TropicalScene_NoSceneryOnGreens`.
5. **Review**: `powershell -File Tools\art-shots.ps1` rebuilds the world and renders review screenshots + `Logs/scene-stats.txt`.

6. **Pass 2 hero layer (unverified):** Blender scripts (`Tools/Blender`) bake PBR textures and hero models into `Art/Generated`; `HeroKit` makes materials, leaf-card foliage and places models by name suffix; `IslandGen.splat` feeds `TerrainSplat`; Hole 1 has a waterfall/pool/mist. `QualityPreset` (Lean/Balanced/Rich) swaps URP assets at runtime. See `Docs/ASSET_WORKFLOW.md` and `Docs/CLOUD_RETURN_REPORT.md`.

A new world = a new palette + kit generator variations + its own `*World` dressing class; golf code is untouched. Blender (5.2 installed) and Universal Modder (needs `FAL_KEY`) are reserved for hero pieces. Licences in `ASSETS.md`.
